# Example reports

These are real runs against Veritarach's live deployment (`https://157-230-241-156.sslip.io`), not fixtures. Generated by `scripts/generate_example_reports.py`.

- [veritarach_holdout.md](veritarach_holdout.md) — confusion matrix against Veracia's independently-built holdout set
- [veritarach_generalization.md](veritarach_generalization.md) — accuracy against 100 samples from a model outside Veritarach's training mix
- [veritarach_adversarial.md](veritarach_adversarial.md) — confidence and accuracy under light paraphrasing

There's no Hecate report here yet. Producing one needs a live Hecate deployment behind it (Postgres, a configured judge provider), and standing that up isn't something this repo does on its own -- the plugin and eval set are ready, but running it for real is a separate step against an actual Hecate instance.

## What these three turned up (as of the 2026-08-15 retrain)

The reports below are from the second run. The first run (against the checkpoint deployed before 2026-08-15) found a model that barely discriminated at all -- confidence stuck in a ~0.5-0.7 band on everything, including completely unambiguous input. That finding is what led to actually root-causing it: a GPU driver/CUDA mismatch had silently degraded the whole training run. Veritarach got retrained properly, verified against its own held-out test set (99.86% F1, genuinely converged this time), and redeployed. Full story in Veritarach's own README and `registration/README.md`.

Re-running the same three checks against the retrained model doesn't show the same failure -- it shows a different one.

**Holdout**: 1 of 24 `ai_generated` samples correctly identified. Recall 0.042. Every one of the 23 misses lands at 0.98+ confidence for `human_written`, not near the decision boundary the way the old checkpoint's errors did -- this model is *sure* it's looking at human writing on cases like a REST API explainer or a travel note about Kyoto, both written specifically for this holdout. All 23 actual `human_written` samples are correct, also at high confidence, so precision is a clean 1.0 and the false positive rate is 0. The asymmetry is the finding: the model learned "call it human unless it looks exactly like training data," not "tell AI text from human text."

**Cross-model generalization** (100 samples from a locally-hosted Phi-4-mini, a model with no part in training): 62% accuracy -- actually higher than the 51% baseline accuracy computed from the holdout run above. Worth not over-reading that as good news: the holdout's 51% baseline is itself dragged down by the same recall collapse (23 of 24 AI samples missed), so "better than baseline" here means "better than a baseline that's already broken," not "handles unfamiliar models well." The more useful number is the raw one -- 38 of 100 clearly AI-generated samples still called human.

**Adversarial**: all 18 samples flipped to `human_written` after paraphrasing, for 0% post-accuracy. One real methodology caveat here, stated plainly rather than smoothed over: `pre_accuracy` reflects classifications made against the *previous* checkpoint, since that's when this dataset was built and its baseline confidence recorded -- it is not a fresh same-model before/after comparison. What the run does show cleanly on its own: the *current* model classifies all 18 of these AI-written samples as human, paraphrased or not, which is just the holdout finding again from a different angle. Rebuilding the adversarial dataset fresh against the current model (correct-classification filter re-run, new baseline confidences) would be needed for a real pre/post number on this specific checkpoint -- not done yet.

None of this says the retrain failed -- 99.86% is a real, independently-verified number on Veritarach's own training distribution (confirmed three separate ways in its own repo, not just this harness). What it says is that number still doesn't transfer to text outside that distribution, and the specific way it fails changed: the old checkpoint was weakly confident and wrong in both directions; the new one is strongly confident and wrong in one direction only, toward under-flagging AI text. For a detector whose whole job is catching AI text, that's arguably a worse failure mode to ship than the old one, even though the training-distribution number went up.
